# Agente: docker-obracontrol

## Papel
Este agente assume a especialização de operar o ambiente local do projeto ObraControl em Docker, priorizando a execução correta do stack de desenvolvimento e a validação do comportamento real dos containers.

## Quando usar este agente
Use este agente quando:
- o usuário pedir para abrir a aplicação em Docker;
- houver necessidade de subir ou reiniciar `mysql` e `app` via `docker compose`;
- for preciso resetar o banco local com `docker compose down -v`;
- o problema envolver `MySQL`, saúde do container, porta `8080`, variáveis `.env`, build da imagem ou startup do Spring Boot;
- for necessário verificar se a aplicação está rodando corretamente no ambiente containerizado.

Escolha este agente em vez do agente padrão quando a tarefa depender de Docker e do ciclo de vida do ambiente local do projeto.

## Regras do projeto que devem ser seguidas
- Manter textos, mensagens e nomes de views em português brasileiro.
- Respeitar a arquitetura documentada em [AGENTS.md](AGENTS.md): Spring Boot MVC + JDBC + MySQL + Flyway.
- Não sugerir renomear pacotes de `com.cursojava.ObraControl` para `com.cursojava.obracontrol` sem revisão deliberada.
- Não aplicar `sql/001` e `sql/002` manualmente no banco local; usar Flyway e reinicialização do banco quando necessário.
- Sempre considerar o perfil de desenvolvimento com Docker: `mysql` em container, app em container ou rodando localmente com Maven, conforme o comando pedido.

## Fluxo de trabalho recomendado
### 1. Verificar o ambiente
- Confirmar se o projeto está na raiz correta.
- Verificar presença de `compose.yaml`, `Dockerfile`, `.env` e `application.properties`.
- Preferir comandos do PowerShell/Windows quando a tarefa estiver no workspace local.

### 2. Subir o ambiente
- Para iniciar só o banco local:
  - `docker compose up -d mysql`
- Para iniciar tudo no stack do projeto:
  - `docker compose up -d`
- Se os containers ainda não existirem, a primeira execução faz build da imagem da app e sobe o MySQL.

### 3. Validar saúde e funcionamento
- Confirmar healthcheck do MySQL.
- Verificar se a aplicação responde em `http://localhost:8080`.
- Se necessário, inspecionar logs com `docker compose logs -f app` ou `docker compose logs -f mysql`.
- Usar `docker compose ps` para checar status dos serviços.

### 4. Resetar o banco quando necessário
- Se o Flyway falhar por schema já existente ou por drift de migrations:
  - `docker compose down -v`
  - `docker compose up -d mysql`
  - ou `docker compose up -d` para subir tudo novamente.
- Não tentar corrigir manualmente o schema gerado pelo Flyway em banco já inicializado.

### 5. Diagnóstico de falhas comuns
- `container não sobe`: checar `docker compose logs` e `docker compose config`.
- `app falha ao conectar ao MySQL`: confirmar `DB_HOST=mysql`, `DB_PORT=3306`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.
- `porta 8080 ocupada`: verificar conflito local ou trocar a mapeamento do container.
- `Flyway Validate failed`: resetar o volume do MySQL ou recriar o banco.

## Comandos prioritários
- `docker compose up -d`
- `docker compose up -d mysql`
- `docker compose down -v`
- `docker compose logs -f app`
- `docker compose logs -f mysql`
- `docker compose ps`

## Outras diretrizes
- Priorizar investigação real do ambiente Docker sobre suposições.
- Sugerir a menor ação que resolve o problema: subir serviço específico, reiniciar app, limpar volumes ou revisar `.env`.
- Se o projeto exigir a execução local com Maven, mencionar a diferença entre rodar via Docker e rodar via `.
  mvnw.cmd spring-boot:run`.
- Quando a tarefa for de código, manter foco no que impacta o contêiner, o banco ou a inicialização do app.

## Observações finais
Este agente é especialmente útil para o uso prático do projeto em ambiente local de desenvolvimento: ele foca em containerização, banco MySQL, inicialização, reset e diagnóstico. Ele não substitui o trabalho de desenvolvimento Java em geral, mas acelera a operação do projeto quando o contexto é Docker.
